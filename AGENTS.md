# TRENZO — инструкции Codex

Эти правила действуют для проекта `fit-report-mvp` и его вложенных каталогов. Объём каждой задачи задаёт запрос владельца продукта.

## Работа с интерфейсом

1. **Работай локально.** Для простой правки найди нужный файл, изучи непосредственно затронутый код и сразу внеси изменение. Не проводи широкое исследование проекта без необходимости.
2. **Сохраняй фирменный стиль.** Используй подтверждённые правила из [DESIGN-SYSTEM.md](design-system/DESIGN-SYSTEM.md) и утверждённый главный экран как визуальный эталон. Ссылка на его снимок и фиксацию — [UI-BASELINE.md](UI-BASELINE.md). Для мелкой правки достаточно обратиться к релевантному разделу; перечитывать всю документацию каждый раз не требуется.
3. **Переиспользуй существующее.** Сохраняй тексты, графические ресурсы, компоненты и поведение. Не добавляй незапрошенные улучшения, новые стили или ресурсы. Не копируй на другие экраны позиционные CSS-компенсации главной страницы.
4. **Береги функциональность.** Не меняй бизнес-логику, API, Supabase, хранение данных, маршруты и назначения действий без отдельного разрешения. Явный запрос на изменение разрешает его в обозначенных границах.
5. **Проверяй по объёму задачи.** Проверяй непосредственно затронутую функциональность. Не запускай браузер, не делай скриншоты и не проводи полный аудит без необходимости. Полный UI-аудит, комплексное тестирование и визуальную проверку нескольких разрешений выполняй только по прямому запросу владельца.
6. **Используй дизайн-навыки по делу.** Применяй UI/UX Pro Max и Impeccable, если задача требует дизайн-решений или оценки интерфейса. Для простой технической замены или локальной корректировки не добавляй лишние этапы исследования.
7. **Передавай результат кратко.** Укажи, что изменено, какие файлы затронуты и что проверено. Перечисляй ограничения только если они есть. Финальное визуальное согласование и утверждение новых экранов остаются за владельцем продукта.
