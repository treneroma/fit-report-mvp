# TRENZO MVP

Статическое приложение: HTML, CSS и JavaScript. Если Telegram недоступен или
проверка клиента не проходит, спортсмен попадает в локальный демо-кабинет.
Тестовые показатели не загружаются и не сохраняются в Supabase; серверные
действия в этом режиме отключены. При успешной проверке остаются доступны
реальные серверные профили. Кабинет тренера — отдельный локальный прототип.

## Прототип тренера

Навигация: **Главная · Клиенты · Отчёты · Схемы · Аналитика**.

- `screens/trainer-data.js` — единые демо-данные и действия над ними.
- `screens/trainer.js` — экраны, переиспользуемая разметка и навигация.
- `styles/trainer.css` — стили, ограниченные тренерским кабинетом.

Подтверждение разбора обновляет очередь и сохраняет решение в истории клиента.
Программы можно редактировать и назначать с отдельным подтверждением.
Анкета тренера, образование, регалии, решения и программы сохраняются локально в ключах
`trenzo-trainer-demo-v1:<Telegram ID или local>`. Реальные данные спортсменов
не читаются и не изменяются. AI и приглашения демонстрационные.

В профиле тренера отображаются ответы анкеты (имя, формат работы и опыт),
образование и регалии. Эти сведения редактируются в одном окне и хранятся
локально. Отдельная анкета при выборе роли и подключение профиля к Supabase
пока не реализованы.

Для локального просмотра: `python3 -m http.server 4173 --bind 127.0.0.1`.
Для проверки состояния и переходов: `node --test tests/*.test.cjs`.

При подключении backend заменять адаптер данных, сохраняя общий источник
профиля, питания, веса и тренировок спортсмена. Сервер должен проверять связь
тренера с клиентом; демо-назначения и локальный Telegram ID не дают доступ к БД.

## Цикл отчётов

Отчёт закрывает семь дней работы клиента. Новая демонстрация разделяет
короткую клиентскую форму и интерфейс принятия решений тренера.

В разделе «Отчёты»: **К разбору · Просрочили · История**. Численный badge
считает только отправленные, ещё не проверенные отчёты. Данные недели,
субъективные ответы, демо-анализ, решение и ответ хранятся раздельно.
При закрытии сохраняются следующий план и память; архивный снимок неизменяем.
Старые автоматические обзоры не считаются поступившими отчётами клиента.

Ссылки на клиентский демо-экран из интерфейса тренера убраны; клиентская
точка входа будет добавлена отдельно. Боевой кабинет спортсмена не изменён.
Отправка локальная; AI-анализ демонстрационный, без внешних запросов.

Архитектура, контракт v1, сценарии проверки и требования к боевой интеграции
описаны в [REPORTS.md](REPORTS.md). SQL и Supabase-функции в репозиторий не добавлены.
